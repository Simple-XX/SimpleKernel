# 阶段 6：设备框架与驱动

> **依赖**：阶段 4（设备框架核心、UART 驱动）+ 阶段 5（仅 VirtIO 阻塞 I/O） | **预计时间**：3 周 | **复杂度**：中高

> **优化说明**：本阶段不再完全依赖阶段 5。设备框架核心（步骤 1-7：Driver trait、DeviceNode、DriverRegistry、PlatformBus、UART 驱动）仅需要内存管理（阶段 3）和中断（阶段 4），可在阶段 4 完成后立即开始。VirtIO 传输/队列（步骤 8-10）也只需要中断。仅 VirtIO 阻塞 I/O 中的任务等待逻辑需要阶段 5 的 TaskManager。本阶段可与阶段 5、阶段 7 并行推进。

## 目标
设备管理器、驱动注册表、平台总线（FDT 枚举）、UART 驱动、VirtIO 子系统。

## 需要创建的文件
- `kernel/src/device/mod.rs`
- `kernel/src/device/manager.rs` — DeviceManager
- `kernel/src/device/registry.rs` — DriverRegistry
- `kernel/src/device/platform_bus.rs` — 基于 FDT 的设备枚举
- `kernel/src/device/node.rs` — DeviceNode
- `kernel/src/device/ns16550a.rs` — NS16550A UART
- `kernel/src/device/pl011.rs` — PL011 UART
- `kernel/src/device/virtio/mod.rs`
- `kernel/src/device/virtio/transport.rs` — VirtIO MMIO 传输层
- `kernel/src/device/virtio/queue.rs` — Split virtqueue
- `kernel/src/device/virtio/blk.rs` — VirtIO 块设备
- `kernel/src/device/virtio/console.rs`
- `kernel/src/device/virtio/gpu.rs`
- `kernel/src/device/virtio/input.rs`
- `kernel/src/device/virtio/net.rs`
- `kernel/src/device/acpi.rs` — ACPI 表结构解析（RSDP, XSDT, FADT, DSDT）
- `kernel/src/io_buffer.rs` — RAII 对齐 I/O 缓冲区（DMA 缓冲区，需要堆分配）

## 验证命令
```bash
# 验证设备枚举和 UART 工作
cargo xtask run --arch riscv64
```

## 退出标准
1. 从 FDT 枚举设备 — 日志显示发现的设备
2. UART 输出通过设备框架工作（不只是早期控制台）
3. VirtIO 块设备读写成功（通过 rootfs.img 验证）
4. 驱动注册表正确匹配 FDT 中的 `compatible` 字符串
5. DeviceInit() 在两个架构上无错误完成
6. ACPI 表结构解析正确
