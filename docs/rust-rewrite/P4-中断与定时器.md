# 阶段 4：中断与定时器

> **依赖**：阶段 3 | **预计时间**：2 周 | **复杂度**：高

## 目标
中断处理（PLIC/GIC）、定时器 tick、系统调用分发。

## 需要创建的文件
- `src/arch/riscv64/interrupt.rs` — PLIC + trap 分发
- `src/arch/riscv64/timer.rs` — SBI 定时器
- `src/arch/riscv64/syscall.rs` — ecall 处理
- `src/arch/riscv64/context.rs` — TrapContext, InitTaskContext
- `src/arch/riscv64/backtrace.rs`
- `src/arch/aarch64/interrupt.rs` — GICv3 + 异常分发
- `src/arch/aarch64/timer.rs` — 通用定时器
- `src/arch/aarch64/syscall.rs` — svc 处理
- `src/arch/aarch64/context.rs` — TrapContext, InitTaskContext
- `src/arch/aarch64/backtrace.rs`
- `src/syscall.rs` — 系统调用号定义 + 分发表

## C++ 参考文件
- `src/arch/riscv64/interrupt.cpp`, `interrupt_main.cpp`, `plic/plic.cpp`
- `src/arch/aarch64/interrupt.cpp`, `interrupt_main.cpp`, `gic/gic.cpp`
- `src/arch/*/timer.cpp`, `syscall.cpp`, `backtrace.cpp`
- `src/include/interrupt_base.h` → `Interrupt` trait
- `src/include/syscall.hpp`
- `src/include/tick_observer.hpp`

## QEMU 预期输出
```
[0][0 0 INFO ] Hello SimpleKernel
...
[N][0 0 INFO ] InterruptInit: PLIC configured, 32 IRQs
[N][0 0 INFO ] TimerInit: tick frequency = 1000 Hz
[N][0 0 INFO ] Tick #1
[N][0 0 INFO ] Tick #2
[N][0 0 INFO ] Tick #3
... (定时器中断持续触发)
```

## 验证命令
```bash
cargo xtask run --arch riscv64
# 观察 "Tick #N" 持续递增 — 定时器中断在工作
# Ctrl+A, X 退出
```

## 退出标准
1. 定时器 tick 日志持续出现（~1000 Hz）
2. PLIC/GIC 外部中断正确分发
3. SpinLock 周围中断禁用/启用正确
4. `switch.S` ABI: 编译时断言确认 `CalleeSavedContext` 的 `size_of` 和 `offset_of!` 与汇编偏移一致
5. SMP: 从核定时器中断在 `TimerInitSMP()` 后触发
6. 调用栈显示正确的函数名

## 你可以修改的内容

- `syscall.rs` — 系统调用号定义、分发表
- `context.rs` — TrapContext 结构体布局
