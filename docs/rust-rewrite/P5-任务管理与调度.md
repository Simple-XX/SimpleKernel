## 任务状态机 (Task FSM)

任务生命周期由 8 个状态和消息驱动的转换定义。Rust 实现使用 `enum TaskState` + `match` 替代 C++ 的 `etl::fsm`。

```plantuml
@startuml task_fsm
hide empty description
skinparam state {
  BackgroundColor<<terminal>> #FFD2D2
  BackgroundColor<<active>> #D2FFD2
  BackgroundColor<<waiting>> #FFFFD2
}

[*] --> UnInit

state UnInit {
}

state Ready <<active>> {
}

state Running <<active>> {
}

state Sleeping <<waiting>> {
}

state Blocked <<waiting>> {
}

state Stopped <<waiting>> {
}

state Zombie <<terminal>> {
}

state Exited <<terminal>> {
}

UnInit --> Ready : MsgSchedule\n(任务初始化完成)

Ready --> Running : MsgSchedule\n(调度器选中)

Running --> Ready : MsgYield\n(主动让出/时间片到期)
Running --> Sleeping : MsgSleep\n(定时挂起，携带 wake_tick)
Running --> Blocked : MsgBlock\n(等待资源，携带 resource_id)
Running --> Zombie : MsgExit\n[has_parent = true]
Running --> Exited : MsgExit\n[has_parent = false]
Running --> Stopped : MsgStop\n(SIGSTOP/SIGTSTP)

Sleeping --> Ready : MsgWakeup\n(定时器到期或显式唤醒)

Blocked --> Ready : MsgWakeup\n(资源可用)

Stopped --> Ready : MsgCont\n(SIGCONT)
Stopped --> Zombie : MsgExit\n[has_parent = true]
Stopped --> Exited : MsgExit\n[has_parent = false]

Zombie --> Exited : MsgReap\n(父任务 wait() 回收)

Exited --> [*] : 任务从 task_table 中移除

@enduml
```

**转换表（完整）：**

| 当前状态 | 消息 | 条件 | 目标状态 | 触发场景 |
|----------|------|------|----------|----------|
| UnInit | MsgSchedule | — | Ready | `TaskManager::AddTask()` |
| Ready | MsgSchedule | — | Running | `Schedule()` 选中任务 |
| Running | MsgYield | — | Ready | 主动让出 / `OnTimeSliceExpired` |
| Running | MsgSleep | — | Sleeping | `sys_sleep(ms)` |
| Running | MsgBlock | — | Blocked | `Mutex::Lock()` 竞争 / I/O 等待 |
| Running | MsgExit | has_parent | Zombie | `sys_exit()` 有父任务 |
| Running | MsgExit | !has_parent | Exited | `sys_exit()` 无父任务 |
| Running | MsgStop | — | Stopped | `SIGSTOP` / `SIGTSTP` |
| Sleeping | MsgWakeup | — | Ready | 定时器到期 / `sys_wakeup()` |
| Blocked | MsgWakeup | — | Ready | 资源释放 / `WakeupOne()` |
| Stopped | MsgCont | — | Ready | `SIGCONT` |
| Stopped | MsgExit | has_parent | Zombie | 被 `SIGKILL` 终止 |
| Stopped | MsgExit | !has_parent | Exited | 被 `SIGKILL` 终止 |
| Zombie | MsgReap | — | Exited | 父任务调用 `sys_wait()` |

**线程安全**：FSM 状态变更通过 `atomic` 缓存（`Ordering::Release` 写入 / `Ordering::Acquire` 读取），读取不需要持锁。

## 阻塞 Mutex 状态机

阻塞 Mutex 与任务调度紧密耦合——竞争时当前任务进入 Blocked 状态。

```plantuml
@startuml mutex_fsm
hide empty description

state Unlocked {
}

state Locked {
}

state "任务 Blocked\n(等待队列)" as Contended

[*] --> Unlocked

Unlocked --> Locked : Lock()\n[CAS 成功]\n设置 owner = current_pid

Locked --> Contended : Lock()\n[CAS 失败，竞争]\n当前任务 → MsgBlock(resource_id)\n进入调度器

Contended --> Locked : WakeupOne()\n[被唤醒后重试 CAS 成功]\n设置 owner = woken_pid

Locked --> Unlocked : Unlock()\n[无等待者]\n清除 owner

Locked --> Locked : Unlock()\n[有等待者]\nWakeupOne() → 唤醒一个任务\n新任务获得锁

note right of Contended
  任务在 resource_id 上阻塞
  进入 TaskFSM 的 Blocked 状态
  调度器切换到其他任务
end note

note right of Locked
  **守卫条件：**
  • 不允许递归加锁
  • Unlock() 必须由 owner 调用
  • 需要任务上下文（不能在中断中使用）
end note

@enduml
```

## 实现步骤
- [ ] 步骤 1：定义 `Scheduler` trait（从 `SchedulerBase` 移植）

```rust
/// 完整的调度器 trait — 必须包含 C++ SchedulerBase 的所有钩子。
pub trait Scheduler: Send + Sync {
    /// 将任务添加到就绪队列。
    fn enqueue(&mut self, task: &mut TaskControlBlock);
    /// 从就绪队列中移除任务（用于阻塞/退出）。
    fn dequeue(&mut self, task: &mut TaskControlBlock);
    /// 选择下一个运行的任务（不从队列中移除）。
    fn pick_next(&mut self) -> Option<&mut TaskControlBlock>;
    /// 就绪队列中的任务数量。
    fn queue_size(&self) -> usize;
    /// 队列是否为空。
    fn is_empty(&self) -> bool;
    /// Tick 更新 — 如果需要抢占则返回 true。
    fn on_tick(&mut self, current: &mut TaskControlBlock) -> bool { false }
    /// 时间片到期 — 如果任务应重新入队则返回 true。
    fn on_time_slice_expired(&mut self, task: &mut TaskControlBlock) -> bool { true }
    /// 优先级继承：当高优先级任务等待该任务时提升其优先级。
    fn boost_priority(&mut self, _task: &mut TaskControlBlock, _new_priority: i32) {}
    /// 释放资源后恢复原始优先级。
    fn restore_priority(&mut self, _task: &mut TaskControlBlock) {}
    /// 当任务被抢占时调用（Running → Ready）。
    fn on_preempted(&mut self, _task: &mut TaskControlBlock) {}
    /// 当任务开始运行时调用（Ready → Running）。
    fn on_scheduled(&mut self, _task: &mut TaskControlBlock) {}
    /// 获取调度器统计信息。
    fn stats(&self) -> &SchedulerStats;
    /// 重置统计信息。
    fn reset_stats(&mut self);
}

/// 调度器统计信息（匹配 C++ SchedulerBase::Stats）
pub struct SchedulerStats {
    pub total_enqueues: usize,
    pub total_dequeues: usize,
    pub total_picks: usize,
    pub total_preemptions: usize,
}
```

## Rust 能力审阅补充（2026-03-25）

> 以下是基于对 C++ `task_control_block.hpp`、`scheduler_base.hpp`、`task.cpp`、`scheduler.cpp`、`task_messages.hpp`、`resource_id.hpp`、`signal.hpp` 的审查。**P5 是复杂度最高的阶段，也是 Rust 优势最大的阶段。**

### 超越 C++ 的设计改进

#### 1. Enum 替代 Union（TCB 调度器数据）

C++ TCB 使用裸 `union SchedData` 存储不同调度器的特定数据，依赖运行时标签区分：

```cpp
// C++ —— 类型不安全，读错字段不会报错
union SchedData {
    struct { int64_t vruntime; uint64_t weight; } cfs;
    struct { uint8_t level; } mlfq;
};
```

Rust 的 tagged union（enum）在编译期保证类型安全：

```rust
/// 编译器保证你不会在 FIFO 任务上读取 vruntime
#[derive(Debug, Clone)]
pub enum SchedulerData {
    Cfs { vruntime: i64, weight: u64 },
    Fifo,
    RoundRobin { remaining_ticks: u64 },
}

impl SchedulerData {
    /// 仅在 CFS 时可访问 vruntime —— 编译期保证
    pub fn vruntime(&self) -> Option<i64> {
        match self {
            Self::Cfs { vruntime, .. } => Some(*vruntime),
            _ => None,
        }
    }
}
```

#### 2. 类型安全的 ResourceId（替代 bit-packing）

C++ 用 8 位类型 + 56 位数据的 bit-packing：

```cpp
// C++ —— Futex 和 Timer 的 data 部分是同一个 uint64_t，容易混用
ResourceId(ResourceType type, uint64_t data);
```

Rust 的 enum 让每种资源类型携带正确类型的数据：

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum ResourceId {
    Mutex(u64),
    Semaphore(u64),
    CondVar(u64),
    ChildExit(Pid),        // 只接受 Pid，不是任意 u64
    IoComplete(u64),
    Futex(VirtAddr),       // 只接受 VirtAddr，不是任意 u64
    Signal(Pid),
    Timer(u64),
    Interrupt(IrqNumber),  // 只接受 IrqNumber
    Custom(u64),
}
```

#### 3. 零成本 FSM（编译期穷举检查）

C++ 的 `etl::fsm` 需要 8 个单独的状态类，加上手动状态列表和原子缓存层作为 workaround。Rust 的 enum + match 直接实现，编译器保证所有状态转换都被处理：

```rust
/// 状态转换 —— 编译器强制处理所有组合
pub fn transition(state: TaskState, msg: TaskMsg) -> Result<TaskState, InvalidTransition> {
    match (state, msg) {
        (TaskState::UnInit, TaskMsg::Schedule) => Ok(TaskState::Ready),
        (TaskState::Ready, TaskMsg::Schedule) => Ok(TaskState::Running),
        (TaskState::Running, TaskMsg::Yield) => Ok(TaskState::Ready),
        (TaskState::Running, TaskMsg::Sleep { wake_tick }) => Ok(TaskState::Sleeping { wake_tick }),
        (TaskState::Running, TaskMsg::Block { resource_id }) => Ok(TaskState::Blocked { resource_id }),
        (TaskState::Running, TaskMsg::Exit { code, has_parent: true }) => Ok(TaskState::Zombie { exit_code: code }),
        (TaskState::Running, TaskMsg::Exit { code, has_parent: false }) => Ok(TaskState::Exited { exit_code: code }),
        (TaskState::Running, TaskMsg::Stop) => Ok(TaskState::Stopped),
        (TaskState::Sleeping { .. }, TaskMsg::Wakeup) => Ok(TaskState::Ready),
        (TaskState::Blocked { .. }, TaskMsg::Wakeup) => Ok(TaskState::Ready),
        (TaskState::Stopped, TaskMsg::Cont) => Ok(TaskState::Ready),
        (TaskState::Stopped, TaskMsg::Exit { code, has_parent: true }) => Ok(TaskState::Zombie { exit_code: code }),
        (TaskState::Stopped, TaskMsg::Exit { code, has_parent: false }) => Ok(TaskState::Exited { exit_code: code }),
        (TaskState::Zombie { .. }, TaskMsg::Reap) => Ok(TaskState::Exited { exit_code: 0 }),
        // 编译器会在遗漏状态转换时发出警告
        (from, msg) => Err(InvalidTransition { from, msg }),
    }
}
```

对比 C++ 需要 ~300 行状态类定义 + 消息分发 + 原子缓存，Rust 仅需 ~20 行 match 表达式，且编译器验证完整性。

#### 4. Option 替代 nullable 指针（TaskAuxData）

C++ 中 `TaskAuxData* aux` 可以为 null，每次访问都需要检查。Rust 用 `Option` 在编译期强制处理缺失情况：

```rust
pub struct TaskControlBlock {
    pub pid: Pid,
    pub context: CalleeSavedContext,
    /// Option 强制调用者处理 None —— 不可能忘记 null 检查
    pub aux: Option<Box<TaskAuxData>>,
    pub state: AtomicTaskState,
    pub sched_data: SchedulerData,
    pub fd_table: FileDescriptorTable,
}
```

#### 5. 信号掩码用 bitflags（替代手动位操作）

C++ 中信号掩码是 `uint64_t`，需要手动移位。Rust 的 `bitflags` 提供类型安全：

```rust
bitflags! {
    #[derive(Debug, Clone, Copy)]
    pub struct SignalMask: u64 {
        const SIGHUP    = 1 << 1;
        const SIGINT    = 1 << 2;
        const SIGQUIT   = 1 << 3;
        const SIGKILL   = 1 << 9;   // 不可屏蔽
        const SIGSTOP   = 1 << 19;  // 不可屏蔽
        const SIGCHLD   = 1 << 17;
        // ...
    }
}

impl SignalMask {
    /// SIGKILL 和 SIGSTOP 不可屏蔽 —— 在方法中强制保证
    pub fn with_unmaskable(self) -> Self {
        self & !(Self::SIGKILL | Self::SIGSTOP)
    }
}
```

#### 6. 调度器 trait 改进（关联类型 + 默认实现）

C++ 的 `SchedulerBase` 用虚函数和 `[[maybe_unused]]` 参数。Rust 可以更精确：

```rust
pub trait Scheduler: Send + Sync {
    /// 关联类型 —— 每个调度器可以定义自己的统计数据结构
    type Stats: Default + Debug;

    fn enqueue(&mut self, task: &mut TaskControlBlock);
    fn dequeue(&mut self, task: &mut TaskControlBlock);
    fn pick_next(&mut self) -> Option<&mut TaskControlBlock>;
    fn queue_size(&self) -> usize;

    /// 默认实现 —— 不需要 [[maybe_unused]]
    fn on_tick(&mut self, _current: &mut TaskControlBlock) -> bool { false }
    fn on_time_slice_expired(&mut self, _task: &mut TaskControlBlock) -> bool { true }
    fn boost_priority(&mut self, _task: &mut TaskControlBlock, _new_priority: i32) {}
    fn restore_priority(&mut self, _task: &mut TaskControlBlock) {}

    fn stats(&self) -> &Self::Stats;
    fn reset_stats(&mut self);
}
```

#### 7. 侵入式链表考量

调度器热路径中，C++ 使用 `etl::list` 的侵入式链表。Rust 标准库没有侵入式链表，但可以：

- **方案 A**：使用 arena 分配器 + 索引。`TaskControlBlock` 存储在固定数组（arena）中，调度队列持有索引而非指针。这是最 Rust-idiomatic 的方案，避免 unsafe。
- **方案 B**：使用 `Pin<Box<T>>` + unsafe 侵入式链表。性能最好但需要仔细维护安全不变式。

**建议**：P5 初始实现使用方案 A（arena + 索引），在性能分析后如果调度器成为瓶颈再考虑方案 B。

```rust
/// Arena 方案 —— 零 unsafe，调度器用索引操作
pub struct TaskArena {
```
