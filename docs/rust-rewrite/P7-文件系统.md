struct VirtioBlockAdapter {

impl fatfs::IoBase for VirtioBlockAdapter {

impl fatfs::Read for VirtioBlockAdapter { /* 调用 device.read_block() */ }

### 文件描述符表
- 每个任务持有独立的 FD 表（`Vec<Option<FileDescriptor>>`）
- FD 0/1/2 预留给 stdin/stdout/stderr
- 最大 FD 数量由 `config.rs` 中的 `MAX_FD_PER_TASK` 常量控制（建议默认 256）
- `FileDescriptor` 包含：VFS 文件引用、当前偏移量、打开标志（读/写/追加）

## Rust 能力审阅补充（2026-03-25）

> 以下是基于对 C++ `vfs.hpp`、`file_descriptor.hpp`、`ramfs/`、`fatfs/` 的审查。

### 超越 C++ 的设计改进

#### 1. Arc 引用计数替代手动 refcount

C++ VFS 中 `Dentry` 有手动的 `refcount` 字段，需要配套 `get()`/`put()` 函数。忘记调用 `put()` 导致内存泄漏，多次 `put()` 导致 use-after-free。Rust 的 `Arc` 自动、线程安全：

```rust
/// Inode 通过 Arc 共享 —— 引用计数自动管理
pub type InodeRef = Arc<Inode>;
pub type DentryRef = Arc<SpinLock<Dentry>>;

pub struct File {
    /// Arc 自动引用计数 —— 无需手动 get/put
    inode: InodeRef,
    offset: u64,
    flags: OpenFlags,
}

// File Drop 时自动减少 Inode 引用计数
// 最后一个 File 关闭时，Inode 自动释放（如果 dentry 也无引用）
```

#### 2. Trait 对象替代函数指针表

C++ VFS 使用 `InodeOps*` 和 `FileOps*` 函数指针表。Rust 用 trait 对象提供更好的类型安全和可扩展性：

```rust
/// 文件系统操作 —— trait 对象替代 C++ 函数指针表
pub trait FileSystem: Send + Sync {
    fn name(&self) -> &str;
    fn create_inode(&self, parent: &Inode, name: &str, file_type: FileType) -> KResult<InodeRef>;
    fn lookup(&self, parent: &Inode, name: &str) -> KResult<Option<InodeRef>>;
    fn read(&self, inode: &Inode, offset: u64, buf: &mut [u8]) -> KResult<usize>;
    fn write(&self, inode: &Inode, offset: u64, data: &[u8]) -> KResult<usize>;
    fn mkdir(&self, parent: &Inode, name: &str) -> KResult<InodeRef>;
    fn unlink(&self, parent: &Inode, name: &str) -> KResult<()>;
    fn readdir(&self, inode: &Inode) -> KResult<Vec<DirEntry>>;
}

/// Inode 持有文件系统 trait 对象引用
pub struct Inode {
    pub ino: u64,
    pub file_type: FileType,
    pub size: AtomicU64,
    pub permissions: u32,
    /// trait 对象替代 void* fs_private + InodeOps*
    pub fs: Arc<dyn FileSystem>,
}
```

对比 C++ 的函数指针表 + `void* fs_private`，Rust 方案消除了类型转换和空指针风险。

#### 3. 路径类型（替代裸字符串）

C++ 中路径是 `const char*`，没有任何验证。Rust 可以定义路径类型：

```rust
/// 内核路径类型 —— 保证以 '/' 开头，无连续 '/'，无 '\0'
#[derive(Debug, Clone)]
pub struct KernelPath {
    components: Vec<String>,
}

impl KernelPath {
    /// 解析路径 —— 构造时验证，使用时安全
    pub fn parse(path: &str) -> KResult<Self> {
        if !path.starts_with('/') {
            return Err(ErrorCode::InvalidPath);
        }
        let components: Vec<String> = path.split('/')
            .filter(|s| !s.is_empty())
            .map(|s| s.to_string())
            .collect();
        Ok(Self { components })
    }

    pub fn components(&self) -> &[String] { &self.components }
    pub fn parent(&self) -> Option<KernelPath> { /* ... */ }
    pub fn filename(&self) -> Option<&str> { /* ... */ }
}
```

#### 4. 文件描述符表用 Option 数组（替代 nullable 指针）

C++ FD 表是指针数组，需要 null 检查。Rust 用 `Option` 在编译期强制处理：

```rust
pub struct FileDescriptorTable {
    /// Option<Arc<File>> —— None 表示空闲槽位
    entries: Vec<Option<Arc<File>>>,
}

impl FileDescriptorTable {
    pub fn alloc(&mut self, file: Arc<File>) -> KResult<Fd> {
        for (i, slot) in self.entries.iter_mut().enumerate() {
            if slot.is_none() {
                *slot = Some(file);
                return Ok(Fd(i as u32));
            }
        }
        Err(ErrorCode::TooManyOpenFiles)
    }

    /// 返回 Option —— 编译器强制调用者处理无效 FD
    pub fn get(&self, fd: Fd) -> Option<&Arc<File>> {
        self.entries.get(fd.0 as usize)?.as_ref()
    }

    pub fn close(&mut self, fd: Fd) -> KResult<()> {
        let slot = self.entries.get_mut(fd.0 as usize)
            .ok_or(ErrorCode::BadFileDescriptor)?;
        *slot = None; // Arc 引用计数自动减少
        Ok(())
    }
}
```

#### 5. FatFS 适配用 trait 实现（零 C FFI）

原计划提到使用 `fatfs` crate（纯 Rust），这是正确的选择。进一步明确适配层设计：

```rust
/// VirtIO 块设备到 fatfs I/O trait 的适配
pub struct VirtioBlockAdapter {
    device: Arc<VirtioBlkDevice>,
    position: u64,
}

impl fatfs::IoBase for VirtioBlockAdapter {
    type Error = ErrorCode;
}

impl fatfs::Read for VirtioBlockAdapter {
    fn read(&mut self, buf: &mut [u8]) -> Result<usize, Self::Error> {
        let sector = self.position / SECTOR_SIZE as u64;
        let offset = (self.position % SECTOR_SIZE as u64) as usize;
        // 读取扇区，拷贝数据
        let n = self.device.read_sectors(sector, buf, offset)?;
        self.position += n as u64;
        Ok(n)
    }
}
```
