## 架构相关细节

### 页表格式
| 架构 | 页表格式 | 级数 | 页大小 | 虚拟地址位宽 |
|------|----------|------|--------|-------------|
| riscv64 | Sv39 | 3 级 | 4KB | 39 位 |
| aarch64 | 4 级页表 (4KB granule) | 4 级 | 4KB | 48 位 |

### 内核地址空间布局
内核使用直接映射（identity mapping）方式：虚拟地址 = 物理地址。这简化了早期启动阶段的内存管理。后续可根据需要添加高半内核映射。

### 帧分配器初始化
帧分配器需要从 FDT 获取可用内存范围（`memory` 节点的 `reg` 属性），排除内核自身占用的区域（从链接脚本符号 `__text_start` 到 `__end`）。

## Rust 能力审阅补充（2026-03-25）

> 以下是基于对 C++ `virtual_memory.hpp/cpp`、`memory.cpp` 的审查，识别出的 Rust 优势。

### 超越 C++ 的设计改进

#### 1. Newtype 地址类型（消除 `void*` 混用）

C++ 中 `MapPage(void* page_dir, void* virt, void* phys, uint32_t flags)` 的三个 `void*` 参数极易传错。Rust 的 newtype 在编译期消除此问题：

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
#[repr(transparent)]
pub struct PhysAddr(usize);

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
#[repr(transparent)]
pub struct VirtAddr(usize);

// PhysAddr 和 VirtAddr 是不同类型 —— 编译器阻止混用
pub fn map_page(vaddr: VirtAddr, paddr: PhysAddr, flags: PageFlags) -> KResult<()> { /* ... */ }
```

在构造函数中内置对齐检查（`new_aligned`），使得非对齐地址在创建时就被拒绝，而不是在使用时才发现。

#### 2. 类型安全的页表项（替代 `uint64_t` 位操作）

C++ 直接操作 `uint64_t` 页表项，需要手动记住哪些位是什么含义。Rust 用 `bitflags` 提供类型安全：

```rust
bitflags! {
    pub struct PageFlags: u64 {
        const VALID     = 1 << 0;
        const READ      = 1 << 1;
        const WRITE     = 1 << 2;
        const EXECUTE   = 1 << 3;
        const USER      = 1 << 4;
        const GLOBAL    = 1 << 5;
        const ACCESSED  = 1 << 6;
        const DIRTY     = 1 << 7;
    }
}

/// 页表项 newtype —— 不可能与普通 u64 混用
#[repr(transparent)]
pub struct PageTableEntry(u64);

impl PageTableEntry {
    pub fn flags(&self) -> PageFlags { PageFlags::from_bits_truncate(self.0) }
    pub fn phys_addr(&self) -> PhysAddr { PhysAddr((self.0 >> 10) << 12) } // Sv39 格式
    pub fn is_valid(&self) -> bool { self.flags().contains(PageFlags::VALID) }
    pub fn is_leaf(&self) -> bool { self.flags().intersects(PageFlags::READ | PageFlags::WRITE | PageFlags::EXECUTE) }
}
```

#### 3. RAII 映射区域（替代手动 unmap）

C++ 中映射和取消映射是分离的操作，容易忘记 unmap 导致泄漏。Rust 的 Drop trait 自动处理：

```rust
/// 映射区域的 RAII 守卫 —— Drop 时自动取消映射
pub struct MappedRegion {
    vaddr: VirtAddr,
    size: usize,
    page_table: &'static PageTable,
}

impl Drop for MappedRegion {
    fn drop(&mut self) {
        self.page_table.unmap_range(self.vaddr, self.size)
            .expect("unmap in drop should not fail");
    }
}
```

#### 4. 架构相关的页表格式用 trait 抽象

C++ 通过 `cpu_io` 命名空间做编译期分发。Rust 可以用 trait + cfg 更明确：

```rust
/// 每个架构实现自己的页表格式
trait PageTableFormat {
    const LEVELS: usize;
    const PAGE_SIZE: usize;
    fn vpn_index(vaddr: VirtAddr, level: usize) -> usize;
    fn make_pte(paddr: PhysAddr, flags: PageFlags) -> PageTableEntry;
}

#[cfg(target_arch = "riscv64")]
struct Sv39;
impl PageTableFormat for Sv39 {
    const LEVELS: usize = 3;
    const PAGE_SIZE: usize = 4096;
    // ...
}
```
